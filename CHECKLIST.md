# 🚀 Deployment Checklist\n\nChoose your deployment platform and follow the checklist.\n\n---\n\n## Option 1: Local (macOS - Recommended for Testing)\n\n### Pre-Flight\n- [ ] Ollama running: `ollama serve` (in separate terminal)\n- [ ] .env configured with real credentials\n- [ ] Requirements installed: `pip install -r requirements.txt`\n\n### Launch\n```bash\nsource venv/bin/activate\npython main.py\n```\n- [ ] Server starts without errors\n- [ ] Check logs: Should see \"Scheduler started successfully\"\n- [ ] Browser/curl: `http://localhost:8000/health` returns healthy\n\n### Verify\n```bash\ncurl http://localhost:8000/jobs | jq  # See scheduled job\ncurl -X POST http://localhost:8000/trigger | jq  # Manual test\n```\n- [ ] Jobs endpoint shows email_summary_job\n- [ ] /trigger endpoint succeeds\n- [ ] Check Slack for test summary\n\n### Keep Running\n```bash\n# Stop: Ctrl+C\n# Run in background: nohup python main.py > autopilot.log 2>&1 &\n# Stop background: pkill -f \"python main.py\"\n```\n- [ ] Process running in background\n- [ ] Logs captured in autopilot.log\n\n---\n\n## Option 2: Docker (Mac/Linux)\n\n### Pre-Flight\n- [ ] Docker installed: `docker --version`\n- [ ] .env file in project root\n- [ ] Dockerfile exists in project root\n\n### Build & Run\n```bash\n# Build\ndocker build -t autopilot:latest .\n\n# Run\ndocker run -d \\\n  --name autopilot \\\n  -p 8000:8000 \\\n  --env-file .env \\\n  -v $(pwd)/autopilot.log:/app/autopilot.log \\\n  autopilot:latest\n```\n- [ ] Image builds successfully\n- [ ] Container starts: `docker ps` shows autopilot\n- [ ] Logs: `docker logs -f autopilot` shows \"running on http://0.0.0.0:8000\"\n\n### Verify\n```bash\ncurl http://localhost:8000/health\ncurl http://localhost:8000/jobs\n```\n- [ ] /health endpoint responds\n- [ ] /jobs shows email_summary_job\n\n### Cleanup\n```bash\n# Stop\ndocker stop autopilot\n\n# Remove\ndocker rm autopilot\n```\n\n---\n\n## Option 3: Railway.app (⭐ Easiest Cloud)\n\n### Pre-Flight\n- [ ] GitHub account created\n- [ ] Code pushed to GitHub repo\n- [ ] .env variables listed (don't commit .env file)\n\n### Deploy\n1. Go to [railway.app](https://railway.app)\n2. [ ] Sign in with GitHub\n3. [ ] Click \"New Project\"\n4. [ ] Select \"Deploy from GitHub repo\"\n5. [ ] Choose your autopilot repo\n6. [ ] Railway detects Python and installs dependencies\n7. [ ] Add environment variables:\n   - [ ] EMAIL_ADDRESS\n   - [ ] EMAIL_PASSWORD  \n   - [ ] EMAIL_IMAP_SERVER\n   - [ ] EMAIL_IMAP_PORT\n   - [ ] SLACK_WEBHOOK_URL\n   - [ ] OLLAMA_MODEL\n   - [ ] OLLAMA_HOST\n   - [ ] SCHEDULE_CRON\n   - [ ] SCHEDULE_ENABLED\n   - [ ] LOG_LEVEL\n\n### Verify\n```bash\n# Get your Railway URL from dashboard\ncurl https://your-railway-url.railway.app/health\n```\n- [ ] App deployed and running\n- [ ] /health endpoint responds\n- [ ] Check Railway logs for errors\n\n### Auto-Deploy\n- [ ] Push to GitHub: `git push origin main`\n- [ ] Railway automatically redeploys\n- [ ] Logs show new deployment\n\n---\n\n## Option 4: Google Cloud Run\n\n### Pre-Flight\n- [ ] Google Cloud account created\n- [ ] gcloud CLI installed: `gcloud --version`\n- [ ] Authenticated: `gcloud auth login`\n- [ ] Project created: `gcloud projects create autopilot-prod`\n\n### Deploy\n```bash\ngcloud run deploy autopilot \\\n  --source . \\\n  --platform managed \\\n  --region us-central1 \\\n  --memory 512Mi \\\n  --timeout 60 \\\n  --allow-unauthenticated \\\n  --set-env-vars \"EMAIL_ADDRESS=...,EMAIL_PASSWORD=...,...\"\n```\n- [ ] Deployment completes\n- [ ] Note the service URL\n- [ ] Check Cloud Run logs for errors\n\n### Verify\n```bash\ncurl https://autopilot-xxxx.a.run.app/health\n```\n- [ ] /health endpoint responds\n- [ ] Logs show app running\n\n### Schedule with Cloud Scheduler\n```bash\ngcloud scheduler jobs create http autopilot-schedule \\\n  --schedule \"0 9 * * 1\" \\\n  --http-method POST \\\n  --uri \"https://autopilot-xxxx.a.run.app/trigger\" \\\n  --location us-central1\n```\n- [ ] Scheduler job created\n- [ ] Manual test: Check Slack for summary\n\n---\n\n## Option 5: AWS Lambda\n\n### Pre-Flight\n- [ ] AWS account created\n- [ ] AWS CLI installed: `aws --version`\n- [ ] Credentials configured: `aws configure`\n\n### Package\n```bash\nmkdir lambda_package\npip install -r requirements.txt -t lambda_package/\ncp -r . lambda_package/\ncd lambda_package && zip -r ../lambda.zip . && cd ..\n```\n- [ ] lambda.zip created (< 50MB for upload)\n- [ ] Contains all dependencies and source\n\n### Deploy\n1. AWS Console → Lambda → Create function\n2. [ ] Function name: `autopilot`\n3. [ ] Runtime: Python 3.11\n4. [ ] Upload lambda.zip\n5. [ ] Handler: `main.app`\n6. [ ] Timeout: 60 seconds\n7. [ ] Memory: 512 MB\n8. [ ] Environment variables: Add all from .env\n9. [ ] Create and deploy\n\n### Verify\n```bash\n# Test function\naws lambda invoke \\\n  --function-name autopilot \\\n  --payload '{}' \\\n  response.json\n\ncat response.json\n```\n- [ ] Function executes successfully\n- [ ] No errors in CloudWatch logs\n\n### Schedule with CloudWatch\n1. CloudWatch → Rules → Create rule\n2. [ ] Name: `autopilot-schedule`\n3. [ ] Schedule: `cron(0 9 ? * MON-FRI *)`\n4. [ ] Target: Lambda function `autopilot`\n5. [ ] Enable rule\n\n---\n\n## Monitoring Checklist (All Platforms)\n\n### Daily\n- [ ] Check /health endpoint responds\n- [ ] Verify last summary posted to Slack\n- [ ] Review logs for errors\n\n### Weekly  \n- [ ] Check execution history: `curl http://your-url/history?limit=20`\n- [ ] Verify schedule is correct: `curl http://your-url/jobs`\n- [ ] Review Slack channel for quality issues\n\n### Monthly\n- [ ] Update Ollama model if new version available\n- [ ] Review logs for patterns\n- [ ] Test manual trigger: `curl -X POST http://your-url/trigger`\n- [ ] Check database size: `ls -lh autopilot*.db`\n\n---\n\n## Troubleshooting\n\n### \"Connection refused\"\n- [ ] Server is running? Check port 8000\n- [ ] Firewall blocking? Check security groups\n- [ ] Wrong URL? Verify endpoint\n\n### \"Failed to connect to Ollama\"\n- [ ] Local: Is `ollama serve` running?\n- [ ] Cloud: Is OLLAMA_HOST correct?\n- [ ] Check logs for connection errors\n\n### \"Invalid credentials\"\n- [ ] Verify EMAIL_PASSWORD is app-specific password\n- [ ] For Gmail: https://myaccount.google.com/apppasswords\n- [ ] Test with telnet: `telnet imap.gmail.com 993`\n\n### \"Schedule not running\"\n- [ ] Check SCHEDULE_ENABLED=true\n- [ ] Verify SCHEDULE_CRON format\n- [ ] Check next_run time: `curl /jobs`\n- [ ] Review scheduler logs\n\n### \"No history showing\"\n- [ ] First run? History will be empty\n- [ ] Run manual trigger: `curl -X POST /trigger`\n- [ ] Wait 10 seconds, then check /history\n- [ ] Verify database permissions\n\n---\n\n## Rollback Checklist\n\nIf deployment fails:\n- [ ] Local: `Ctrl+C` to stop server\n- [ ] Docker: `docker stop autopilot && docker rm autopilot`\n- [ ] Railway: Revert to previous deployment in dashboard\n- [ ] Cloud Run: Previous revision available in history\n- [ ] AWS Lambda: Previous version in function versions\n\n---\n\n## Success Criteria ✅\n\n- [ ] Server responds to /health\n- [ ] Scheduled job appears in /jobs\n- [ ] Manual /trigger runs without error\n- [ ] Summary posted to Slack\n- [ ] Logs show no errors\n- [ ] Can update schedule with /schedule endpoint\n- [ ] History retrieves summaries with /history\n\n**Once all are checked, you're deployed!** 🎉\n\n---\n\n## Quick Reference\n\n```bash\n# All platforms - once deployed, use these\ncurl https://your-url/health              # Health check\ncurl https://your-url/jobs                # View jobs\ncurl -X POST https://your-url/trigger     # Manual run\ncurl https://your-url/history?limit=10    # View summaries\ncurl -X POST \"https://your-url/schedule?cron=0%2018%20*%20*%20*\"  # Update schedule\n```\n\n---\n\nReady?
